# 模块：ui（表现层与交互入口）

UI 的核心职责是：

- 把交互转换为 `Command`（`core/types/command.gd`）
- 调用 `GameEngine.execute_command` 推动规则
- 读取 `GameState` 渲染界面（不直接改 state）

## 主要入口场景与脚本

- 主菜单：`ui/scenes/main_menu.tscn`（脚本 `ui/scenes/menus/main_menu.gd`）
  - 新游戏：跳转到 GameSetup
  - 联机：跳转到 OnlineLobby
  - 载入存档：`GameEngine.load_from_file` 后把引擎放入 `Globals.current_game_engine`
  - 回放：设置 `Globals.pending_replay_file_path` 后进入 Game 场景
- 联机大厅：`ui/scenes/online/online_lobby.tscn`（脚本 `ui/scenes/online/online_lobby.gd`）
  - 使用 `NetClient/NetContext` 连接服务器、拉取房间列表、创建/加入/观战房间
  - 房主编辑 RoomConfig（玩家数/seed/模块等）并广播同步
  - 开始游戏后进入 `ui/scenes/game/game.tscn`（客户端以回放方式应用 server 广播的命令）
- 新游戏设置：`ui/scenes/setup/game_setup.tscn`（脚本 `ui/scenes/setup/game_setup.gd`）
  - 选择玩家数/种子/模块/玩家资料（名称、颜色、Logo）
  - 写入 `Globals.*`，然后 `SceneManager.goto_game()`
- 游戏主场景：`ui/scenes/game/game.tscn`（脚本 `ui/scenes/game/game.gd`）
  - 若 `Globals.current_game_engine` 存在则复用（载入存档入口）
  - 否则按 `Globals` 配置创建新引擎并 `initialize(...)`
  - 回放入口：若 `Globals.pending_replay_file_path` 有值则自动启动回放播放器

Game 场景内部的 controller 拆分与职责边界见：`docs/architecture/21-ui-game-scene.md`

## Game 场景与引擎交互方式

`ui/scenes/game/game.gd` 作为“协调器”，把 UI 拆分为多个 controller（map/panels/overlays/menu 等），并统一提供：

- `_execute_command(command: Command) -> Result`：唯一执行入口
  - 回放模式禁止执行
  - 处于历史位置时禁止执行（除非进入时间线编辑模式）
  - 执行成功后会按需重建日志时间线
- `_update_ui()`：从 `game_engine.get_state()` 读取并刷新 UI

## 日志/时间线（StepTimeline）

当前 UI 的日志面板可按需用引擎状态与命令历史重建时间线视图：

- `gameplay/replay/step_timeline_build.gd`：构建 step 时间线
- `gameplay/replay/event_timeline_build.gd`：构建事件时间线（供 step 视图使用）

这套设计配合 `rewind_to_command()` 能更可靠地展示“回退后/分支后”的日志与状态。

## UI 与 autoload 的边界

- 允许 UI 使用 `Globals`/`SceneManager`/`EventBus`（便利性优先）
- core 侧尽量不依赖 Node；若必须输出事件，通过 `GameEngine.emit_event`（可注入 sink）
- 新局/载入/回放入口都应清理 `EventBus` 历史，避免跨对局污染（引擎初始化与主菜单均有处理）
